# Зум-переход к системам — план реализации

> **Для агентов:** ОБЯЗАТЕЛЬНАЯ ПОД-СКИЛЛ: используйте superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans, чтобы выполнять план задача за задачей. Шаги размечены чекбоксами (`- [ ]`).

**Цель:** заменить веер карточек-кадров и модальный проигрыватель на узлы систем в сцене и полноэкранный экран системы, куда камера прилетает зумом.

**Архитектура:** один автономный `цепочка.html` без сборки и зависимостей. Вся сцена рисуется в SVG внутри `<g id="камера">`; уровни показа — три состояния одной трансформации этой группы. Узлы систем рисуются в той же группе, поэтому отдельной механики зума не появляется. Экран системы — HTML-слой поверх, который въезжает из точки узла и является конечным состоянием перелёта, а не окном.

**Стек:** ванильный HTML/CSS/JS, без сборки, без npm, без зависимостей. Three.js и прочего здесь нет. Проверка — замер DOM через браузер и снимки экрана.

## Глобальные ограничения

- Всё придуманное в проекте называется по-русски: переменные, функции, константы, поля данных, классы CSS, заголовки коммитов. Латиница — только у пришедшего извне: имена продуктов (AIAN, TUMAR, ABAI), свойства API, имя репозитория.
- Комментарии объясняют «почему», а не «что». Отклонённые варианты записываются.
- Палитра и шрифты не изобретаются: `--циан:#4FE3FF`, `--мята:#3EE6B8`, `--янтарь:#F0AE4A`, `--голубой:#8FBAF0`, `--виолет:#9B7BE8`, `--зелёный:#3ED598`, `--красный:#FF5A4F`, фон `#050810`/`#0C1626`, текст `#D7E2F2`, приглушённый `#7C8DA6`. Шрифты Unbounded и Golos Text самохостятся из `медиа/шрифты`.
- Цвет несёт один смысл. Стадия цепочки, готовность материала и ограничение показа не делят цвет.
- У каждого проекта показывается эффект. Числовые эффекты остаются с пометкой «оценка» — снимать её нельзя.
- Имён руководителей проектов в показе нет: репозиторий публичный.
- Правка не считается сделанной, пока результат не увиден. О непроверенном говорить прямо.
- Правки разной природы — разными коммитами.

## Геометрия, посчитанная заранее

При зуме в передел `масштаб = 1.9`, объект ставится в точку viewBox `(312, 410)`, фокус объекта — `(цx, 275)`.

Видимая область сцены в пользовательских координатах:
- по x: `цx − 164 … цx + 657` (ширина 821);
- по y: `143 … 407` (высота 263).

**Отсюда следствие, определившее расстановку:** дуга над объектом не помещается — на объект приходится `y 185…371`, сверху остаётся 42 единицы. Поэтому узлы разворачиваются **вправо от объекта** с вертикальным прогибом, в пределах `y 275 ± 95` и `x цx+235 … цx+616` вместе с подписью. Всё влезает с запасом 40 единиц по правому краю.

**Сквозные слои.** У полосы объекта нет, поэтому камера даёт лёгкий наезд `масштаб = 1.25` с центром на полосе, а узлы встают строкой над ней. Это уточнение спеки: в ней было сказано «камера не двигается», но без наезда узлам негде встать, а требование заказчика — «все движения по зум ин».

  function местаУзлов(б){
    var список = видимые(б), н = список.length, места = [];
    for(var и = 0; и < н; и++){
      var т = н === 1 ? 0 : (и / (н - 1)) * 2 - 1;   /* −1 … +1 */
